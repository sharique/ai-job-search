# StepStone.de URL Reference

Public, unauthenticated, server-rendered pages used by this skill. German market only.

## robots.txt (fetched 2026-07-17)

Relevant rules from `https://www.stepstone.de/robots.txt`:

```
Disallow: /jobs/vollzeit/
Disallow: /jobs/teilzeit/
Disallow: /jobs/home-office/
Disallow: /jobs/*?*
Allow: /jobs/*?q=*
Disallow: /jobs/*?q*&*
...
Disallow: /search-results
Disallow: /search-results/*
Disallow: /listing
Disallow: /listing/*
```

**Implication:** the plain path form `/jobs/<slug>` or `/jobs/<slug>/in-<location-slug>`
(no query string at all) is **not** matched by any `Disallow` rule and is the only search
form this skill uses. `/search-results` and `/listing` (StepStone's newer, JS-driven
results routes) are explicitly disallowed and are never requested. Detail pages
(`/stellenangebote--...-inline.html`) are not mentioned in robots.txt and are unrestricted.

## Search

```
GET https://www.stepstone.de/jobs/<query-slug>[/in-<location-slug>]
```

- `<query-slug>`: free-text query, lowercased and hyphenated (e.g. `Solution Architect` -> `solution-architect`).
- `<location-slug>`: same slugification, prefixed with `in-` (e.g. `Berlin` -> `in-berlin`). Omit the whole segment to search all of Germany.
- No query-string parameters are used (see robots.txt note above) — this means no server-side `--jobage` or radius filter is available; StepStone's other filters (`?radius=`, `?ag=`, etc.) all fall under the disallowed `/jobs/*?*` pattern.

Returns a server-rendered HTML page. There is **no `application/ld+json` `JobPosting` data
on the search-results page** — only page-level `WebPage`/`BreadcrumbList`/`FAQPage`
structured data, plus a `"searchResultsTotalJobCount":<n>` integer embedded in an
analytics payload (`data-atx-onpageview-payload` attribute), which the CLI extracts for
`meta.totalAvailable`.

Each of the ~25 results on page 1 is a chunk anchored on:

```html
<a ... href="/stellenangebote--<slug>--<id>-inline.html" data-at="job-item-title">
  <div>...title text...</div>
</a>
...
<span data-at="job-item-company-name">...company text (behind an <svg> icon + nested spans)...</span>
<span data-at="job-item-location">...location text (behind an <svg> icon)...</span>
<span data-at="job-item-timeago"><time>...relative posted date, e.g. "vor 13 Stunden"...</time></span>
```

The `data-at`/`data-testid` attributes are StepStone's own test hooks and are stable;
the surrounding CSS class names (e.g. `res-xaz43y`) are generated by Emotion CSS-in-JS
per build and **must not** be relied on. `<style>` and `<svg>` blocks are stripped before
text extraction (see `stripNoise` in `helpers.ts`).

**Pagination:** no `page=`/`seite-2`-style URL was found; page 1 embeds
`"searchResultsDisplayedPageNumber":1` and a fixed `"ssaResultsPerPage":25` in the same
analytics payload, with further pages loaded via a client-side "load more" interaction.
No static, robots.txt-compliant URL for page 2+ exists — `search --page 2` therefore
returns an empty result set with an explicit `meta.warning` rather than silently
re-serving page 1.

## Detail

```
GET https://www.stepstone.de/stellenangebote--<any-slug>--<id>-inline.html
```

The slug segment between `--` and `--<id>-inline.html` is cosmetic; StepStone resolves
the posting by the trailing numeric ID alone (verified: a dummy slug still 200s and
returns the correct posting).

Returns a page with a clean `<script type="application/ld+json">` block:

```json
{
  "@type": "JobPosting",
  "title": "...",
  "datePosted": "2026-07-17T08:48:47.777Z",
  "validThrough": "2026-08-16T08:48:47.777Z",
  "employmentType": "FULL_TIME",
  "industry": "...",
  "description": "<p>...HTML...</p>",
  "hiringOrganization": { "name": "...", "url": "...", "logo": "..." },
  "jobLocation": { "address": { "addressLocality": "...", "addressRegion": "...", "postalCode": "...", "streetAddress": "..." }, "geo": { "latitude": ..., "longitude": ... } }
}
```

`parseJobDetail` parses this block directly (`JSON.parse`), rather than scraping HTML —
far more robust than the search-results parsing. `description` is HTML and is converted
to plain text with paragraph breaks preserved.

## Notes

- No authentication required.
- Respect rate limits — the CLI backs off on 429/5xx with exponential backoff + jitter.
- German market only. Query/location text is typically German (e.g. `"München"` also
  works, and StepStone's slugifier accepts umlauts as literal characters — this skill's
  `slugify()` uses a Unicode-aware letter/number match so umlauts pass through unchanged
  rather than being stripped).
