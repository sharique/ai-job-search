# Template: sharique

- **Type:** CV
- **Engine:** pdflatex
- **Page limit:** 2 page(s)
- **Fonts:** TeX Gyre Heros (system font, part of standard TeX Live - substitutes for the original design's Arial/system-ui, since Arial itself isn't legally redistributable via TeX)
- **Class/packages:** `article` base class; standard packages only - `geometry`, `xcolor` (table option), `graphicx`, `tikz`, `hyperref`, `titlesec`, `microtype`, `tabularx`. No `enumitem` or `tcolorbox` (not present on this machine's TeX Live install) - see "Known pitfalls" for the workarounds used instead.

## Origin

Recreated in LaTeX from an HTML/CSS resume export (`all.html` / `style.css`, originally produced by a resume-builder tool - not moderncv). There was no LaTeX source to register directly, so the design was rebuilt from the CSS's exact colors, font sizes, and layout rules.

Updated 2026-08-01 against a newer export of the same design (`index.html` / `style.css`, no photo) to fix drift between the LaTeX output and the source: the photo header was dropped (the current source design has none), a certification-link color bug was fixed, the Skills grid was rebuilt to stop misaligning when one cell's text wraps to more lines than its neighbor, and Languages was rebuilt from an inline `Name (Level)` line into a proper grid. See "Known pitfalls" below for each.

## Compile command

    cd <output dir> && pdflatex -interaction=nonstopmode <file>.tex

## Style rules

- **Colors** (from source CSS, exact hex): accent blue `#185FA5` (name/section titles/company names/links), gray `#6B7280` (dates, locations, skill items), dark text `#1A1A1A` (body), award-box background `#E6F1FB`.
- **Header:** name (22pt bold) + headline (11pt, blue) + contact row (8.5pt, gray, items separated by `\quad`) with the work-authorisation note forced onto its own line via an explicit `\\` (don't rely on natural wrap - the line length that wraps depends on how many contact items are present). No photo - full `\linewidth`. A 1.2pt blue rule spans the full width below the header.
- **Section titles:** bold, blue, small (8pt), typed in UPPERCASE directly in the `\section{...}` argument (not auto-transformed - see pitfalls), wrapped in `\textls[150]{...}` for letter-spacing, with a thin light-gray rule underneath.
- **Skills:** `\skillrow{cat1}{items1}{cat2}{items2}` - two independent top-aligned minipages per row-pair (not a shared `tabularx` row - see pitfalls), bold category over gray items. Stack two `\skillrow` calls, then an optional full-width row below spanning both columns (e.g. "Technologies & Foundational").
- **Certifications:** `\certrow{name1}{date1}{name2}{date2}` - same minipage row-pair pattern as `\skillrow`, regular (non-bold) weight. Pass `\href{URL}{Name}` for a linked cert (renders in accent blue automatically) or plain text for an unlinked one (e.g. "in progress" - renders in dark text). Stack as many `\certrow` calls as needed, two certs per row.
- **Professional Experience / Projects:** `\entryrow{title}{dates}` puts the entry title bold-left and the date range gray-right on one line (space-between layout) - pass `\href{URL}{title}` instead of plain text when the entry has a public link (Projects), it renders in accent blue automatically. `\entrysub{company + location}` follows in blue, with the location portion switched to gray mid-string via an embedded `\color{graytext}` - compose this string in the template body, e.g. `\entrysub{Company \color{graytext}\textbullet\ Location}`. Entries with no company/location line (e.g. an "Earlier Experience" roll-up) skip `\entrysub` entirely.
- **Award/highlight callout:** `\awardbox{title}{text}` - use sparingly, at most once per role, only for a genuinely distinct highlight (matches the source's single "OKR of the Quarter" usage).
- **Bullets:** use the `compactitem` environment (not plain `itemize` - see pitfalls), tight 2pt item spacing, small bullet glyph.
- **Languages:** grid, not inline prose - `\langcol{name}{level}` stacks name (bold) over level (gray) at natural width, laid out with `\hspace{18pt}` between calls (see pitfalls for why not `tabularx`/fixed-fraction minipages).

## Known pitfalls

- **No `enumitem` on this machine's TeX Live install.** The template defines a `compactitem` environment (plain `itemize` with manually overridden `\itemsep`/`\topsep`/`\parsep`/`\leftmargin`) instead of `enumitem`'s `\setlist`. Use `compactitem`, not `itemize`, throughout - if `itemize` is used directly it will still compile but with default (looser) spacing that no longer matches the design.
- **No `tcolorbox` on this machine's TeX Live install.** The award callout (`\awardbox`) is built with a two-column `tabular` using `colortbl`'s `\columncolor` (a 2pt blue column + a light-blue content column) instead. This is a standard, dependency-light idiom - if `tcolorbox` is confirmed available in a future environment it could replace this for cleaner code, but there is no need to change it.
- **Section titles are typed in UPPERCASE by hand** (e.g. `\section{\textls[150]{PROFESSIONAL SUMMARY}}`), not auto-uppercased by `titleformat`. Nesting `\MakeUppercase` inside a `titlesec` format string to wrap the section argument is a known fragile hack (unclosed-brace trick) - typing headers in caps directly is more robust and was chosen deliberately. If a drafter adds a new section, remember to type its title in caps.
- **`\textls` (microtype letter-spacing) triggers a harmless `hyperref` warning** ("Token not allowed in a PDF string (Unicode): removing `\textls`") for the PDF bookmarks/outline. This does not affect the visible page content - only the (unused) PDF outline entries. Safe to ignore.
- **No photo by default** - the current source design doesn't have one, so the header uses the full `\linewidth`. Adding one back for a specific application: wrap the header text block in a `0.80\linewidth` minipage, add a `0.15\linewidth` minipage to its right containing the old clip idiom (`\begin{tikzpicture}\clip[rounded corners=1.5pt] (0,0) rectangle (2.1cm,2.1cm); \node[anchor=south west,inner sep=0] at (0,0) {\includegraphics[width=2.1cm,height=2.1cm]{photo.jpg}};\end{tikzpicture}`), and load `tikz`/`graphicx` (already in the preamble). Don't leave a bare `\includegraphics` pointing at a nonexistent file - it hard-fails the compile.
- **Skills/Certifications use independent minipages per row-pair, not a shared `tabularx` row.** An earlier version put both grid columns in one `tabularx` row so that a category/cert spanning multiple rows shared row height across the whole table; when one cell's text wrapped to more lines than its neighbor, every row below it started at the wrong vertical offset relative to the other column - a visible staggered/misaligned grid. `\skillrow`/`\certrow` end each row-pair with its own `\par\vspace{...}`, so a tall cell only affects the gap before the *next* row-pair, not the internal alignment of rows further down.
- **Certification links: don't wrap `\href` in `\color{darktext}`.** An earlier version did this on the first certification, which silently overrode the accent-blue link color from `\hypersetup{colorlinks=true, urlcolor=accent}` and rendered it in dark text instead - wrong regardless of source. Pass `\href{URL}{Name}` bare for a linked cert (blue is automatic); only use plain text (no `\href`) for a cert with no URL, which correctly inherits dark text with no override needed.
- **Languages use natural-width `tabular` columns (`\langcol`), not fixed-fraction minipages.** A fixed fraction (e.g. `0.22\linewidth` for 4 columns) works until one language's level string is long ("B1, currently attending B2 course"), at which point it wraps to two lines inside its column even though the row has room - the source CSS's flexbox sizes each column to its own content instead. `\langcol` does the same via a natural-width `tabular[t]`; if a future draft's combined language row is long enough to overflow `\linewidth` (unlikely at 4-5 languages, but possible with many), shorten level strings or drop to two rows rather than shrinking the font.
- **Original HTML/CSS design also had a `@media print` mode** (smaller fonts, tighter margins, A4 0.6cm/0.8cm page margins) that produces a denser ~3-page result for the full master CV. This template instead uses the more readable on-screen CSS sizing as its baseline (10-22pt range) so that a 2-page tailored CV (per this framework's hard page limit) stays comfortably readable - don't reach for the print-mode sizes to force-fit content; cut content per `05-cv-templates.md`'s relevance-weighted cutting rules instead.
